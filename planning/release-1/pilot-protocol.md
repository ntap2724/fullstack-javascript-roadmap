# Release 1 pilot protocol

A Release 1 pilot validates the learner path; it does not certify job readiness or advance the release by itself.

## Participant

Recruit a learner who knows C++, Python, or Java and does not yet have fullstack JavaScript experience. Record their prior experience and supported operating system.

## Procedure

1. Start from a fresh clone on a supported operating system.
2. Follow only the committed README and learner instructions.
3. Permit no undocumented maintainer intervention.
4. Log every blocker, its elapsed time, the attempted resolution, and the smallest useful hint level.
5. Retain the complete evidence package, command output, architecture overview, and a short technical explanation by the learner.
6. Hold a post-completion review covering setup, concepts, failure modes, assessment clarity, and evidence quality.

## Advancement boundary

Release 1 cannot move from `experimental` to `validated` until at least one complete pilot has finished with the required evidence and the resulting blockers have been reviewed through the dependency-ordered backlog.
